# scripts/systemvm

## Overview

Thin Bash wrappers around the `systemvmctl` binary (`src/bin/systemvmctl.rs`).
Each script resolves the repo root, creates the output directories it needs,
and shells out to `cargo run --bin systemvmctl`. `fetch-image.sh` is the only
script that touches the network: it downloads the archive pinned in
`docs/specs/systemvm-image.lock.yaml`, verifies it, extracts the kernel and
initramfs, and has `systemvmctl verify-image` check them. The others call one
subcommand each: `build`, `launch-config`, or `boot-smoke`. Optional positional
arguments are forwarded as flag values. The Makefile targets `systemvm-fetch`,
`systemvm-build`, `systemvm-launch-config`, and `systemvm-boot-smoke` call these
scripts with no arguments, so Makefile invocations always use the defaults
below.

## Interface

- All three scripts compute `ROOT_DIR` as the repo root two levels above the script and consume no environment variables.
- `fetch-image.sh`: `$1` -> `LOCK_PATH` (default `${ROOT_DIR}/docs/specs/systemvm-image.lock.yaml`). Runs `cargo run -q --bin systemvmctl -- lock-env --lock <LOCK_PATH>` and `eval`s its `VESPER_IMAGE_*` lines; downloads `VESPER_IMAGE_URL` to `${ROOT_DIR}/build/systemvm/cache/<basename>` with `curl -fsSL --retry 3` unless a cached copy already has `VESPER_IMAGE_SHA256`; verifies the source digest (`sha256sum`, or `shasum -a 256` on macOS); extracts `VESPER_IMAGE_KERNEL_MEMBER` and `VESPER_IMAGE_INITRD_MEMBER` into the cache with `bsdtar` (or a `tar` that is bsdtar) and verifies `*_MEMBER_SHA256`; unpacks each member per `*_UNPACK` (`none` copies, `zboot-gzip` runs `python3 -I unpack-zboot.py`) to `${ROOT_DIR}/build/systemvm/<*_FILE>`; copies the source to `${ROOT_DIR}/build/systemvm/${VESPER_IMAGE_BOOT_MEDIA_FILE}` when set; runs `cargo run -q --bin systemvmctl -- verify-image --lock <LOCK_PATH> --dir ${ROOT_DIR}/build/systemvm --out ${ROOT_DIR}/build/systemvm/image-manifest.json`. Exits 1 without bsdtar.
- `fetch-packages.sh`: `$1` -> packages lock (default `${ROOT_DIR}/docs/specs/systemvm-packages.lock.yaml`). Reads `cargo run -q --bin systemvmctl -- package-list --lock <LOCK>` (`file<TAB>url<TAB>sha256` lines), downloads each file whose cached copy under `${ROOT_DIR}/build/systemvm/cache/apks/` is missing or has a different digest (`curl -fsSL --retry 3`); then for every `archive-list` line downloads the archive into `build/systemvm/cache/archives/`, verifies its digest, extracts the member with `tar` and copies it to `cache/archives/<name>/<file>`; prints `fetch-packages: <n> downloaded`, then runs `systemvmctl verify-packages --archives-dir`.
- `build-overlay.sh`: `$1` -> image lock (default `${ROOT_DIR}/docs/specs/systemvm-image.lock.yaml`). `eval`s `systemvmctl lock-env`; exits 0 with a message when the lock has no overlay section; exits 2 unless the pinned initramfs exists; verifies the packages and archive members; runs `python3 -I build-initramfs.py --overlay-dir <dir> --apk <each package> --file <each archive member>:<guest path>:<mode> --file docs/specs/design-v0.baselines.lock.yaml:/var/lib/vesper/baselines.lock.yaml:0644 --base-initrd <pinned initramfs> --apkovl-path <path> --out-apkovl ${ROOT_DIR}/build/systemvm/localhost.apkovl.tar.gz --out-initrd ${ROOT_DIR}/build/systemvm/<overlay file>`; then `systemvmctl verify-image --require-overlay` rewrites the manifest.
- `build-initramfs.py`: standard-library Python; builds a USTAR tar (owner root, mtime 0, sorted entries, mode 755 for executables and directories, 644 otherwise, symlinks kept) of the overlay tree (skipping its top-level `README.md`) plus `var/lib/vesper/apks/<file>` for every `--apk` and every `--file SRC:GUEST_PATH[:MODE]` at its guest path (parent directories created, octal mode, default 0644), gzips it with mtime 0, wraps it in a newc cpio archive at `--apkovl-path` (gzip, mtime 0) and writes `--base-initrd` bytes followed by that archive to `--out-initrd`; prints both outputs' SHA-256 and sizes. Exits non-zero when the overlay dir or a package is missing.
- `resolve-apks.py --branch B --arch A --base-index ISO_APKINDEX --index main=PATH --index community=PATH --cache DIR --out LOCK [--include-base PKG ...] [--extra-yaml FILE] PKG...`: standard-library Python; resolves the dependency closure of `PKG...` (names, `so:`/`cmd:`/path provides, version constraints ignored beyond the name, conflicts skipped), treats packages in the base index as already on the boot media unless named by `--include-base` (packages on the ISO that the live system does not install, such as `e2fsprogs`), downloads the closure into `DIR`, writes the packages lock (schema 2) sorted by name with URL, SHA-256 and size, and appends `--extra-yaml` verbatim (`systemvm/archives.yaml`, the Firecracker binaries). Run by hand when bumping packages; not part of any Make target.
- `up.sh [TIMEOUT]` (default `180`): exits 2 unless `${ROOT_DIR}/build/vmlauncher/vesper-vmlauncher` and `build/systemvm/launch-config.json` exist; exits 0 with "already running" when `run/systemvm/vmlauncher.pid` is alive; truncates `run/systemvm/vmlauncher.log`; starts `vesper-vmlauncher --config <launch config> --keep-running --timeout-seconds TIMEOUT` with `nohup`, stdin from `/dev/null` and stdout/stderr appended to the log, writes its pid; polls once per second until the log holds `"status":"probe-ok"` (or `"status":"ready"` when the config has no probe) and the config's `vsock_bridge_path` exists as a socket; prints the status lines and exits 0, or kills the launcher and exits 1 on early exit or timeout.
- `down.sh [WAIT]` (default `30`): exits 0 when there is no pid file or the pid is dead (removing a stale file); runs `systemvmctl control --config <launch config> shutdown`, falling back to `SIGTERM` when the agent is unreachable; waits up to WAIT seconds for the pid to exit, then `SIGTERM` and 10 more seconds; exits 1 if the launcher is still alive.
- `docker-up.sh`: exits 2 without `build/systemvm/launch-config.json`, a `vsock_bridge_path` in it, or the bridge socket; exits 0 with "already running" when `run/vesper/vesper-proxy.pid` is alive; `cargo build -q --bin vesper-proxy`; starts `target/debug/vesper-proxy --listen ${DOCKER_SOCKET:-run/vesper/docker.sock} --upstream vsock://<cid>:${VESPER_DOCKER_PORT:-2375} --vsock-socket-dir <bridge dir> --validate-upstream` detached (stdin `/dev/null`, output to `run/vesper/vesper-proxy.log`), writes the pid, waits up to 10 s for the socket, prints `DOCKER_HOST=unix://…` and `ls -l` of the socket.
- `docker-down.sh`: SIGTERM to the recorded pid (SIGKILL after 5 s), removes the pid file and the socket; always exits 0 unless a command fails.
- `build-trivial-image.sh`: reads the lock (`systemvmctl lock-env`), extracts `apks/aarch64/busybox-1*.apk` and `musl-1*.apk` from the pinned ISO with `bsdtar`, unpacks them (skipping apk metadata members), adds `bin/sh` and `bin/echo` symlinks, and writes a deterministic USTAR `build/systemvm/trivial-rootfs.tar` (root owner, mtime 0, sorted) with standard-library Python; exit 2 without the ISO, 1 without busybox.
- `docker-smoke.sh`: GH #15 checklist against `${DOCKER_SOCKET:-run/vesper/docker.sock}` with the `docker` CLI (`DOCKER_BIN`): `socket_exists_owner_only` (mode 600), `docker_version`, `docker_info`, `docker_import` of the trivial tarball as `vesper/trivial:local`, `trivial_container_runs` (`docker run --rm … /bin/busybox echo vesper-container-ok`), `no_raw_host_sockets` (only `docker.sock`, `3.sock` and `vesperd.sock` under `run/`), `raw_guest_port_denied` (`systemvmctl control --port 2376 handshake` must fail); writes `run/systemvm/docker-smoke-report.json` (`steps[]`, `passed`) and exits non-zero on any failure.
- `reliability-suite.sh [CYCLES]` (default `50`, or `CYCLES` env): exits 2 unless the launcher, launch config and trivial image exist; runs `make docker-down` and `make systemvm-down`; writes `run/systemvm/leak-before.json` (counts and details of `vesper-vmlauncher --config` and `target/debug/vesper-proxy` processes, sockets and `*.pid` files under `run/`); runs `boot-smoke.sh CYCLES 60` (copying the report to `run/systemvm/reliability-boot-report.json`); runs `make systemvm-up`, `systemvmctl control suite --keepalive-seconds 10`, `systemvmctl control services-suite`, `make docker-up`, `docker-smoke.sh`, `make docker-down`, `make systemvm-down`, recording each failure; writes `leak-after.json`; calls `reliability_report.py` with every available report; logs to `run/systemvm/reliability.log`; exit status is the assembler's (0 only when `passed`).
- `reliability_report.py --out REPORT --cycles N --boot-report P --leak-before P --leak-after P [--control-report P] [--services-report P] [--docker-report P] [--host TEXT] [--commit SHA] [--failure TEXT ...]`: standard-library Python; sections `boot_stress` (ok when `failed == 0` and `iterations == cycles`; mean, max, threshold; with at least 10 cycles `drift_first5_ms`, `drift_last5_ms`, `drift_ok`), `control_suite`, `services_suite`, `docker_smoke` (from each report's `passed` and failed steps; `not_run` when absent), `leaks` (ok when every `after` count is zero), `failures[] {step, reason, evidence}`, `passed`; prints `FAIL <step>: <reason> (see <evidence>)` lines; exit 1 unless passed. `--self-test` runs its unit tests.
- `unpack-zboot.py INPUT OUTPUT`: standard-library Python; requires the `MZ`/`zimg` header and `gzip` compression type, gunzips the payload at the header's offset/size, requires the `ARM\x64` magic at offset 56 of the result, writes it, prints `unpacked … (<n> bytes)`. Exit 1 on any format mismatch, 2 on usage.
- `build-image.sh`: no arguments -> `cargo run --bin systemvmctl -- verify-image --dir ${ROOT_DIR}/build/systemvm --out ${ROOT_DIR}/build/systemvm/image-manifest.json`. With `$1` -> `KERNEL_PATH`, optional `$2` -> `INITRD_PATH`, `$3` -> `ROOTFS_PATH`: `systemvmctl build --kernel … [--initrd …] [--rootfs …]`.
- `generate-launch-config.sh`: no arguments -> `systemvmctl launch-config --from-lock --dir ${ROOT_DIR}/build/systemvm --console-log ${ROOT_DIR}/run/systemvm/console.log --out ${ROOT_DIR}/build/systemvm/launch-config.json`, after checking that `image-manifest.json` exists (exit 2 otherwise). With positional `KERNEL [INITRD] [ROOTFS]` the explicit form is used.
- `boot-smoke.sh`: `$1` -> `--iterations` (default `5`), `$2` -> launcher timeout in seconds (default `60`; `systemvmctl --timeout-seconds` is set 10 s higher as a backstop), `$3` -> `--command` (default `${ROOT_DIR}/build/vmlauncher/vesper-vmlauncher`), `$4` -> `--args=<value>` (default `--config,${ROOT_DIR}/build/systemvm/launch-config.json,--timeout-seconds,<TIMEOUT>`, comma-separated and passed as a single `--args=` token). `MAX_BOOT_MS` (env) sets `--max-boot-ms`; when unset it is read from the lock through `systemvmctl lock-env` (`VESPER_IMAGE_MAX_BOOT_MS`). With the default command it exits 2 unless the launcher binary and the launch config exist. Runs `cargo run --bin systemvmctl -- boot-smoke ... --max-boot-ms <N> --log ${ROOT_DIR}/run/systemvm/boot.log --report ${ROOT_DIR}/run/systemvm/boot-report.json`.
- Exit codes: no explicit `exit` statements; under `set -e` each script exits with the status of the first failing command, otherwise with the exit status of `cargo run`.
- Makefile entry points: `make systemvm-fetch`, `make systemvm-overlay` (`fetch-packages.sh` then `build-overlay.sh`), `make systemvm-prepare` (fetch, overlay, launch config, launcher), `make systemvm-build`, `make systemvm-launch-config`, `make systemvm-boot-smoke`, `make systemvm-up` (`up.sh`), `make systemvm-down` (`down.sh`), `make systemvm-control-suite` (`systemvmctl control suite`), `make systemvm-services-suite` (`systemvmctl control services-suite`), `make systemvm-trivial-image` (`build-trivial-image.sh`), `make docker-up` / `make docker-down` (`docker-up.sh`, `docker-down.sh`), `make docker-smoke` (`docker-smoke.sh`), `make systemvm-reliability` (`reliability-suite.sh`, `CYCLES` variable), `make systemvm-microvm-suite` (`systemvmctl control microvm-suite`), `make systemvm-rootfs-suite` (`systemvmctl control rootfs-suite`).

## Invariants

- All shell scripts use `set -euo pipefail` (`docker-smoke.sh` uses `set -uo pipefail` so every step is recorded).
- All file-path arguments are absolute under the computed `ROOT_DIR`. `fetch-image.sh`, `build-image.sh` and `generate-launch-config.sh` `cd "${ROOT_DIR}"`; `boot-smoke.sh` never `cd`s, so its `cargo run` executes in the caller's cwd and fails outside the crate tree.
- `build-image.sh` and `generate-launch-config.sh` run `mkdir -p` on their output directories before `systemvmctl` writes to them.
- `fetch-image.sh` never trusts a download: the source and member digests are checked in bash, the unpacked-file digests plus `expected_image_id` in Rust, and any mismatch exits non-zero before the manifest is written. `generate-launch-config.sh` with no arguments requires a manifest (so a fetch happened) but `launch-config` itself only checks that strings are non-blank. `boot-smoke.sh` with the default command requires the launcher binary and the launch config.
- `fetch-image.sh` is idempotent: with a cached archive of the pinned digest it performs no network access.

## Side Effects

- `fetch-packages.sh` creates `${ROOT_DIR}/build/systemvm/cache/apks` and downloads about 55 MB into it; `build-overlay.sh` writes `${ROOT_DIR}/build/systemvm/localhost.apkovl.tar.gz` and `${ROOT_DIR}/build/systemvm/initramfs-vesper` (about 66 MB) and rewrites the manifest.
- `fetch-image.sh` creates `${ROOT_DIR}/build/systemvm/cache`, downloads about 80 MB into it, extracts `boot/` members there, writes the unpacked kernel, the initramfs and a copy of the ISO to `${ROOT_DIR}/build/systemvm/`, and spawns `cargo run -q --bin systemvmctl` twice (`lock-env`, `verify-image`) plus `python3 -I unpack-zboot.py`; `verify-image` writes `${ROOT_DIR}/build/systemvm/image-manifest.json`.
- `boot-smoke.sh` (default command) starts a Virtualization.framework VM per iteration through the launcher, which truncates and writes `${ROOT_DIR}/run/systemvm/console.log`.
- `reliability-suite.sh` boots the VM `CYCLES` times, leaves nothing running, and writes `run/systemvm/{reliability.log,reliability-report.json,reliability-boot-report.json,leak-before.json,leak-after.json}`.
- `docker-up.sh` leaves a detached `vesper-proxy` running with the owner-only ingress socket `run/vesper/docker.sock` and writes `run/vesper/vesper-proxy.{pid,log}`; `docker-smoke.sh` imports an image named `vesper/trivial:local` into the guest's Docker and runs one container.
- `up.sh` leaves a detached launcher process running (a VM with NAT networking and the owner-only bridge socket `run/systemvm/vsock/3.sock`) and writes `run/systemvm/vmlauncher.{pid,log}`; `down.sh` powers the guest off and removes the pid file.
- `build-image.sh` creates `${ROOT_DIR}/build/systemvm` and spawns `cargo run --bin systemvmctl build`, which writes `${ROOT_DIR}/build/systemvm/image-manifest.json`.
- `generate-launch-config.sh` creates `${ROOT_DIR}/build/systemvm` and `${ROOT_DIR}/run/systemvm`, and spawns `cargo run --bin systemvmctl launch-config`, which writes `${ROOT_DIR}/build/systemvm/launch-config.json` with `${ROOT_DIR}/run/systemvm/console.log` as the console log path.
- `boot-smoke.sh` creates `${ROOT_DIR}/run/systemvm` and spawns `cargo run --bin systemvmctl boot-smoke`, which writes `${ROOT_DIR}/run/systemvm/boot.log` and `${ROOT_DIR}/run/systemvm/boot-report.json`.
- Every `cargo run` may compile the crate, writing to `target/`.

## Verification

- Run: `make systemvm-prepare` (or `make systemvm-fetch`, `make systemvm-overlay`, `make systemvm-launch-config`), `make systemvm-build`, `make systemvm-boot-smoke`; `make systemvm-up && make systemvm-control-suite && make systemvm-down`; `make systemvm-up && make docker-up && make systemvm-trivial-image && make docker-smoke && make docker-down && make systemvm-down`; `make systemvm-reliability`; `python3 -I scripts/systemvm/reliability_report.py --self-test` (also in CI)
- CI: `.github/workflows/systemvm-image.yml` runs `systemvm-fetch`, `systemvm-overlay`, `systemvm-build` and `systemvm-launch-config` on Linux (with `libarchive-tools`) and asserts the manifest `image_id` equals the lock's `expected_image_id`; `boot-smoke` with the launcher runs only on macOS developer hardware.
- Broader regression for `systemvmctl` and the `systemvm` module: `cargo test`
