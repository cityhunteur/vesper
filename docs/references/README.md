# References

This directory is for external reference notes that help explain design or process choices but are not themselves the normative source of truth.

Examples:
- upstream API or runtime references,
- notes extracted from benchmark or spec reading,
- migration notes for tooling.

Normative Vesper behavior still lives in:
- `docs/specs/design-v0.md`
- `docs/specs/firecracker-feature-parity.md`
- execution plans and milestone reports

## Current reference notes

- `harness-engineering-adaptation.md` — how the bundle maps harness-engineering ideas onto Vesper
- `vesper-review.md` — repo review framed around agent-first delivery and parity truth
- `testing.md` — smoke-test plan for the installed harness overlay
- `milestones.md` — suggested milestone sequence after adoption
- `install.md` — original bundle installation notes kept for migration history
