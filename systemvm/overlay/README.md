# systemvm/overlay

## Overview

The Alpine `apkovl` overlay applied to the System VM at boot. `scripts/systemvm/build-initramfs.py`
packs this tree (plus the pinned extra packages under `var/lib/vesper/apks/`) into
`localhost.apkovl.tar.gz`, appends it to the pinned initramfs as a second cpio archive at
`/vesper/localhost.apkovl.tar.gz`, and the kernel command line (`apkovl=/vesper/localhost.apkovl.tar.gz`
in `docs/specs/systemvm-image.lock.yaml`) makes the Alpine init unpack it over the tmpfs root before
OpenRC starts. See ADR 0002. The root stays a tmpfs; only the state directories that `vesper-data` moves onto
the persistent data disk survive a reboot (GH #164).

## Interface

- `etc/.default_boot_services`: empty marker; keeps the init's default boot services (devfs, mdev, modloop, …) enabled although an overlay is present.
- `etc/hostname`: `vesper`.
- `etc/rc.conf`: `rc_cgroup_mode="unified"` (Docker 28 needs cgroup v2; the live image's hybrid layout has no devices controller).
- `etc/runlevels/sysinit/cgroups`: enables the OpenRC `cgroups` service, which the live image does not run.
- `etc/network/interfaces`: `lo` loopback and `eth0` DHCP from the Virtualization.framework NAT; the `networking` service is started by `vesper-services` (not from a runlevel), so its DHCP wait does not delay the login prompt; it provides `net` for `docker`.
- `etc/init.d/vesper-services` (+ `etc/runlevels/default/vesper-services`): oneshot that `need`s `vesper-packages` and starts `networking` (then `/run/vesper/net-ready`), runs `vesper-data mount` (the persistent data disk, GH #164, logged as `vesper: DATA …`), then starts `containerd` and `docker` in a detached `setsid sh -c` with `env -i PATH=… rc-service <svc> start` (inside the runlevel change a plain `rc-service` only schedules the start; detached so the login prompt waits for neither DHCP nor dockerd); logs `vesper: networking up`, `vesper: service <svc> started` or the failure to the console; creates `/run/vesper/services-ready` when both daemons are up (the probe and `HEALTH` wait for it). Both daemons come from the pinned packages' OpenRC scripts: `supervisor=supervise-daemon` (respawn on crash) with `log_proxy` to `/var/log/containerd.log` and `/var/log/docker.log`.
- `etc/init.d/vesper-packages` (+ `etc/runlevels/default/vesper-packages`): OpenRC oneshot that runs `apk add --quiet --no-progress --force-non-repository /var/lib/vesper/apks/*.apk` (the files are not in a repository, so apk needs the flag; they are verified against the Alpine keys on the boot media); on success creates `/run/vesper/packages-ready`; logs `vesper: …` lines to `/dev/console`; fails the service otherwise. Other Vesper services `need` it, which is how OpenRC orders them after the install.
- `etc/init.d/vesper-agent` (+ `etc/runlevels/default/vesper-agent`): `supervise-daemon`-supervised `socat VSOCK-LISTEN:<port>,reuseaddr,fork EXEC:/usr/local/bin/vesper-agent` (port from `VESPER_AGENT_PORT`, default 1024), `respawn_delay=1`, unlimited respawns; `need localmount vesper-packages`.
- `etc/init.d/vesper-docker-relay` (+ `etc/runlevels/default/vesper-docker-relay`): `supervise-daemon`-supervised `socat VSOCK-LISTEN:<port>,reuseaddr,fork UNIX-CONNECT:/var/run/docker.sock` (port from `VESPER_DOCKER_PORT`, default 2375); `need localmount vesper-packages vesper-services`. The raw Docker and containerd sockets stay guest-local; this relay is the only path to Docker from the host.
- `var/lib/vesper/firecracker/{firecracker,jailer}` (from the packages lock's `archives`, placed by `build-initramfs.py --file`, mode 0755): Firecracker v1.16.0 aarch64 release binaries.
- `usr/local/bin/vesper-microvm`: jailed microVM manager; `prepare` (kernel from `/media/vda/boot/vmlinuz-virt` via `od`/`tail`/`head`/`gunzip`, busybox initramfs via `cpio` with the virtio-mmio, virtio-blk, crc32c, ext4 and vsock modules and `modules.dep` from the modloop), `launch ID [--exit] [--rootfs PATH] [--cmd BASE64] [--vsock]` (`--rootfs` copies the ext4 into the jail as `/rootfs.ext4`, attaches it as the root drive, passes `vesper_rootfs=1`; the init then prints `VESPER-ROOTFS-OK <image id>` and `VESPER-ROOTFS-EXEC-OK`, or `VESPER-ROOTFS-MOUNT-FAILED`; `--cmd` needs `--rootfs`, passes `vesper_cmd=BASE64`, and the init chroots into the rootfs, prints `VESPER-WORKLOAD-START`, the output and `VESPER-WORKLOAD-EXIT <code>`, then powers off; `--vsock` adds `{"vsock":{"guest_cid":3,"uds_path":"/v.sock"}}` and `vesper_vsock=1`, the init loads `vsock`, `vmw_vsock_virtio_transport_common` and `vmw_vsock_virtio_transport` and prints `VESPER-VSOCK-OK|FAILED`; `status ID` then reports `vsock=present|absent` for `/srv/jailer/firecracker/ID/root/v.sock`) (`LAUNCHED ID pid=N boot_ms=N` after the `VESPER-MICROVM-OK` marker, else `FAILED ID` plus the log tail), `status ID` (`RUNNING|EXITED|ABSENT`), `isolation ID` (JSON: `uid`, `root`, `jail_files`, `cgroup`, `seccomp_mode`, `uid_ok`, `chroot_ok`, `cgroup_ok`, `seccomp_ok`), `stop ID` (SIGTERM, SIGKILL after 10 s), `crash ID` (SIGKILL), `cleanup ID` (`CLEAN ID` or `DIRTY ID <process|chroot|cgroup|mount|socket>`, exit 1), `log ID [N]`. Jails live under `/srv/jailer/firecracker/ID/root`, console logs under `/var/log/vesper-microvm-ID.log`, cgroups under `/sys/fs/cgroup/firecracker/ID`.
- `usr/local/bin/vesper-rootfs`: OCI image to ext4 pipeline; `import-trivial` (`IMPORTED <image id>`; busybox with every applet linked, musl, `/tmp`, `/proc`, `/dev`), `build IMAGE [--no-cache]` (`BUILT <path> sha256=<h> bytes=<n> cached=<bool>`, or `ERR image not found: …`, `ERR export failed: …`, `ERR mke2fs failed: …`), `provenance PATH` (the sidecar JSON, else `debugfs`), `inspect PATH` (loop-mount listing). Store `/var/lib/vesper/rootfs/`; baselines from `/var/lib/vesper/baselines.lock.yaml`.
- `var/lib/vesper/baselines.lock.yaml`: copy of `docs/specs/design-v0.baselines.lock.yaml` for embedded provenance.
- `usr/local/bin/vesper-workload`: microVM-per-container manager; `run NAME IMAGE -- CMD…` (`STARTED NAME microvm=wl-NAME pid=N image=ID`, or `ERR workload NAME exists`, `ERR rootfs build failed: …`, `ERR launch failed: …`, `ERR workload did not start: …`), `ps` (`NAME RUNNING|EXITED|STOPPED pid=N|- image=ID`), `logs NAME`, `wait NAME [TIMEOUT]` (`EXITED NAME code=N`), `stop NAME` (`STOPPED NAME teardown=CLEAN`), `rm NAME` (`REMOVED NAME` or `ERR leftovers for NAME: …`), `isolation NAME`. Store `/var/lib/vesper/workloads/` (`NAME.json` record, `NAME.ext4` private rootfs copy).
- `usr/local/bin/vesper-fcparity`: Firecracker API probes; `api ID METHOD PATH [BODY|-] [TIMEOUT]` (`STATUS <code>` then the body; `STATUS 000` plus `ERR …` when no response), `conformance ID` (`CHECK <name> ok|fail <detail>` × 19 then `CONFORMANCE passed=N failed=M firecracker_version=V`; exit 0 only when `failed=0`), `perf N` (`SAMPLE i boot_ms= cycle_ms=` lines then `PERF n= boot_p50_ms= boot_p95_ms= boot_max_ms= cycle_p50_ms= create_rate_per_min= wall_ms= failures=`). Uses `socat` and `/var/lib/vesper/firecracker/firecracker --version`.
- `usr/local/bin/vesper-ctr`: containerd driver for the Vesper shim; `import` (`docker save` the trivial image into containerd; `IMPORTED <ref>`), `run NAME WORDS…` (`ctr run --rm --runtime io.containerd.vesper.v2 <ref> NAME sh -c "WORDS"`; `RC <code>` then `OUT <line>` lines), `start NAME WORDS…` (`ctr run -d`; `STARTED NAME pid=N`), `state NAME` (`STATE NAME <STATUS> pid=N`, `ABSENT` with exit 1), `kill NAME` (SIGKILL, waits up to 10 s for STOPPED; `KILLED NAME`), `delete NAME` (task then container delete; `DELETED NAME`), `try CTR-ARGS…` (any `ctr -n vesper` command; `RC` and `OUT` lines), `leftovers` (`CLEAN`, or `DIRTY firecracker=N shims=N jails=N tasks=N containers=N` with exit 1), `import-layered` (commits `/etc/layer2-marker` onto the trivial image, imports it; `IMPORTED <ref> layers=2`), `run-image REF NAME WORDS…` and `start-image REF NAME WORDS…` (any ref), `meta NAME` (the task's `vesper-rootfs.json` line from `/run/containerd/io.containerd.runtime.v2.task/vesper/NAME/`), `cache` (`CACHE <n>` then `<key> bytes= sha256=` per cached drive), `shim-pid NAME` (`SHIMPID NAME <pid>`), `kill-shim NAME` (SIGKILL; `KILLED-SHIM NAME <pid>`), `wait-gone NAME [T]` (`GONE NAME` once `ctr task ls` no longer lists it), `state-file NAME` (the task's `vesper-task.json`), `inflight-start NAME WORDS…` (background `ctr run --rm`; `INFLIGHT NAME` once the task is listed), `inflight-result NAME [T]` (`RC` and `OUT` lines when it ends), `metrics NAME` (`METRICS NAME memory_bytes= cpu_usec= pids=` parsed from `ctr task metrics --format json`).
- `usr/bin/containerd-shim-vesper-v2`: the Go shim from `shim/`, placed by `build-overlay.sh` (not in this tree).
- `etc/init.d/vesper-port-relay` + `usr/local/bin/vesper-port-relay-conn`: the System VM gateway for published ports (ADR 0005); `socat VSOCK-LISTEN:${VESPER_PORT_RELAY:-2400},reuseaddr,fork EXEC:/usr/local/bin/vesper-port-relay-conn` under supervise-daemon in the default runlevel; the helper reads one line `PORT <n>` (1..65535, digits only, else exit 1) and `exec socat STDIO TCP:127.0.0.1:<n>`.
- `usr/local/bin/vesper-data` (GH #164): the persistent data disk, named on the kernel command line as `vesper_data=/dev/vdX`. `mount`: an empty disk (no filesystem found by `blkid`) is formatted ext4 with label `vesper-data` and lazy inode-table and journal init; an ext4 disk labelled `vesper-data` is mounted as it is; any other filesystem or label is refused and never formatted. It mounts the disk at `/var/lib/vesper-data` (`noatime`) and bind-mounts `/var/lib/docker`, `/var/lib/containerd`, `/var/lib/vesper/rootfs`, `/var/lib/vesper/rootfs-cache`, `/var/lib/vesper/workloads` and `/var/lib/vesper/state` onto subdirectories of it. Replies `DATA formatted <dev>`, `DATA mounted <dev>` (also when already mounted), `DATA absent` (no `vesper_data=` on the command line) or `DATA refused <dev> <reason>` (`no-device`, `mkfs-failed`, `foreign:<type>:<label>`, `mount-failed`, `bind-failed:<dir>`), and records the outcome in `/run/vesper/data-state`. When the disk is absent or refused, the state stays in tmpfs. `status` prints `DATA <recorded outcome>` plus `used=<KiB> avail=<KiB>` while the disk is mounted; `stop` syncs, unmounts the bind mounts and the disk, and prints `DATA stopped`.
- `usr/local/bin/vesper-share`: virtio-fs shares; `mount TAG PATH [ro|rw]` (`modprobe virtiofs`, `mkdir -p`, `mount -t virtiofs [-o ro]`; `MOUNTED TAG PATH mode=…` also when already mounted; `ERR virtio-fs tag … is not present (tags: …)` lists `/sys/fs/virtiofs/*/tag`), `list` (`SHARE TAG PATH mode=ro|rw` from `/proc/mounts`), `umount PATH`, `probe TAG PATH` (`PROBE module= tag_present= mounted= sysfs= inotifyd= notify=started|stopped`), `touch PATH...` (GH #150: replays each path in three steps: `touch -c -a -r P P`, an atime-only set whose reply refreshes the guest's cached attributes; `touch -c -m -r P P`, which writes the mtime back so the guest kernel emits `IN_MODIFY`; and `touch -c -m P` only when the file's size changed between the two. Contents never change; the host mtime stays equal to the last host write except in the two cases in `docs/SECURITY.md`; the host atime and ctime change. One line per path, `TOUCHED <path>` (`TOUCHED <path> raced` when the third step ran), `SKIPPED <path> share-root|read-only-share`, `MISSING <path>`, `REJECTED <path> not-absolute|dotdot|outside-shares` or `ERR <path> touch-failed`; exit 1 when any path is rejected or fails), `notify` (the same for one absolute path per stdin line; greets `VESPER-SHARE-NOTIFY 1` and prints `NOTIFY touched= skipped= missing= rejected= errors=` on EOF). Paths are resolved with `realpath` and must lie inside a read-write virtio-fs mount from `/proc/mounts` (`VESPER_SHARE_MOUNTS` overrides the table for the self-test); mount points containing `*`, `?` or `[` are compared literally.
- `etc/init.d/vesper-share-notify` (+ `etc/runlevels/default/vesper-share-notify`): `supervise-daemon`-supervised `socat VSOCK-LISTEN:<port>,reuseaddr,fork,max-children=4 EXEC:'/usr/local/bin/vesper-share notify'` (port from `VESPER_SHARE_NOTIFY_PORT`, default 2401; at most four handlers at a time); `need localmount vesper-packages`. The launcher's share watcher holds one connection to it and writes the paths of host edits (`launcher/README.md`).
- `etc/init.d/vesper-binfmt`: mounts `binfmt_misc` and registers `/usr/bin/qemu-x86_64` for x86-64 ELF (magic and mask of the standard qemu entry) with flags `OCF`, skipping entries already present; prints `vesper: binfmt_misc registered N interpreter(s)` on the console; `stop` unregisters `qemu-*`.
- `usr/local/bin/vesper-arch`: `status` (`NATIVE <uname -m> binfmt_misc=enabled|absent`, then `INTERP <name> <enabled|disabled> flags= interpreter= version=` per `/proc/sys/fs/binfmt_misc/qemu-*`), `mode ARCH` (`linux/` prefix and `amd64`/`arm64` aliases accepted; `MODE <arch> native|emulated:<interp>|unsupported (no binfmt_misc interpreter for …; supported: …)`, exit 1 when unsupported).
- `usr/local/bin/vesper-agent`: one process per connection; greets `VESPER-AGENT 1 <hostname>` and answers `PING`, `VERSION`, `ECHO <n>` (reads and returns `n` bytes), `HEALTH` (JSON: `packages_ready`, `services_ready`, OpenRC states of `containerd`, `docker`, `vesper-agent`, `containerd_ok` from `ctr --connect-timeout 2s version`, `docker_ok` and `docker_version` from `docker version`, `kvm` when `/dev/kvm` exists, which it does only when the launcher enabled nested virtualization), `KILL <containerd|docker>` (SIGKILL to the daemon, replies `KILL <name> <pid>`), `MICROVM <args…>` (runs `vesper-microvm <args>`, replies `MICROVM <rc> <count>` then the output lines), `ROOTFS <args…>` (same shape for `vesper-rootfs`), `WORKLOAD <args…>` (same shape for `vesper-workload`), `FCPARITY <args…>` (same shape for `vesper-fcparity`), `CTR <args…>` (same shape for `vesper-ctr`), `SHARE <args…>` (same shape for `vesper-share`), `DATA <args…>` (same shape for `vesper-data`, GH #164), `ARCH <args…>` (same shape for `vesper-arch`), `LOGS <messages|containerd|docker> <n>` (`LOGS <count>` then the lines), `DROP` (closes), `SHUTDOWN` (`BYE` then `poweroff`), `QUIT`; unknown commands get `ERR unknown command`, unknown services or logs `ERR unknown service|log`.

## MicroVM execution (ADR 0006)

`vesper-microvm prepare` copies runc, socat, tini-static, `vesper-console` and their shared libraries
into the microVM initramfs. Package-lock and ISO verification cover their inputs.
`runtime.sha256` records copied bytes; the guest verifies it before execution.
A content stamp rebuilds an old initramfs when its scripts or runtime binaries change.
`vesper-microvm-init` holds the guest init separately from the manager script.

`launch ID --rootfs PATH --runc-smoke` runs a fixed hello-world through runc and records kernel config
and available memory on the serial console. `--guest-exec` instead enables the private session service,
adds vsock and runs `tini-static` with socat on port 1025.
`vesper-guest-session` writes OCI configs verbatim, opens three socat stream relays and invokes runc.
It supports start, exec, signal, abort and terminal resize control requests.
`vesper-console` receives the terminal master through the existing containerd libraries.
It uses a guest-local Unix socket for resize; no descriptor crosses the VM boundary.
See [shim/README.md](../../shim/README.md) for the protocol and lifecycle contract.

`vesper-ctr run-stdio|run-tty|interactive|exec|exec-tty|exec-signal|signal-test|run-orphan|exit-with-exec`
provides the GH #23 hardware probes. `vesper-ptyrun` gives ctr a terminal, initially 24×80,
then resizes it to the supplied dimensions after three seconds.
The terminal proof binary comes from `shim/` and is installed by `build-overlay.sh`.

## Invariants

- Every file in this tree lands at the same path under `/` in the guest; the builder sets owner root, mode from the repository (executable bit preserved) and mtime 0, so the archive is deterministic.
- No secrets, no host paths, no package binaries live here: packages come from the cache that `scripts/systemvm/fetch-packages.sh` verifies against the packages lock.
- Scripts must be POSIX `sh` (busybox). A service that depends on an installed package must `need vesper-packages`.

## Side Effects

- At guest boot: `eth0` gets a DHCP lease; cgroup v2 is mounted; packages are installed into the tmpfs root on every boot (`/run/vesper/packages-ready`); `vesper-data mount` formats or mounts the data disk and prints `vesper: DATA …` on the console; `containerd` and `dockerd` start under `supervise-daemon` (`/run/vesper/services-ready`, logs under `/var/log/`); console lines prefixed `vesper:` are printed; `socat` listens on vsock port 1024 and spawns the agent per connection, and on vsock port 2375 relaying to the Docker socket.
- `vesper-data mount` formats an empty data disk once; afterwards writes by containerd, dockerd and the Vesper tools to the persistent directories change the disk image on macOS. `vesper-services stop` runs `vesper-data stop` after stopping the daemons.
- `KILL` sends SIGKILL to a daemon; supervise-daemon restarts it within about half a second.
- `MICROVM launch` starts a Firecracker process as uid 10000 in a jail with a cgroup; `cleanup` removes all of it.

## Verification

- `make systemvm-overlay` builds the archive; `make systemvm-boot-smoke` boots with it and the probe in the image lock requires `/run/vesper/packages-ready`, the installed binaries, the agent service and both runtime services; `make systemvm-up && make systemvm-services-suite` proves crash recovery.
