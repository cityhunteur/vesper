# systemvm/overlay

## Overview

The Alpine `apkovl` overlay applied to the System VM at boot. `scripts/systemvm/build-initramfs.py`
packs this tree (plus the pinned extra packages under `var/lib/vesper/apks/`) into
`localhost.apkovl.tar.gz`, appends it to the pinned initramfs as a second cpio archive at
`/vesper/localhost.apkovl.tar.gz`, and the kernel command line (`apkovl=/vesper/localhost.apkovl.tar.gz`
in `docs/specs/systemvm-image.lock.yaml`) makes the Alpine init unpack it over the tmpfs root before
OpenRC starts. See ADR 0002. The root stays a tmpfs; only the state directories that `vesper-data` moves onto
the persistent data disk survive a reboot (GH #164).

## Interface

- `etc/.default_boot_services`: empty marker; keeps the init's default boot services (devfs, mdev, modloop, …) enabled although an overlay is present.
- `etc/hostname`: `vesper`.
- `etc/rc.conf`: `rc_cgroup_mode="unified"` (Docker 28 needs cgroup v2; the live image's hybrid layout has no devices controller).
- `etc/runlevels/sysinit/cgroups`: enables the OpenRC `cgroups` service, which the live image does not run.
- `etc/network/interfaces`: `lo` loopback and `eth0` DHCP from the Virtualization.framework NAT; the `networking` service is started by `vesper-services` (not from a runlevel), so its DHCP wait does not delay the login prompt; it provides `net` for `docker`.
- `etc/init.d/vesper-services` (+ `etc/runlevels/default/vesper-services`): oneshot that `need`s `vesper-packages`, loads the `tun` module (GH #173), and starts `networking` (then `/run/vesper/net-ready`), runs `vesper-data mount` (the persistent data disk, GH #164, logged as `vesper: DATA …`), then starts `containerd` and `docker` in a detached `setsid sh -c` with `env -i PATH=… rc-service <svc> start` (inside the runlevel change a plain `rc-service` only schedules the start; detached so the login prompt waits for neither DHCP nor dockerd); logs `vesper: networking up`, `vesper: service <svc> started` or the failure to the console; creates `/run/vesper/services-ready` when both daemons are up (the probe and `HEALTH` wait for it). Both daemons come from the pinned packages' OpenRC scripts: `supervisor=supervise-daemon` (respawn on crash) with `log_proxy` to `/var/log/containerd.log` and `/var/log/docker.log`.
- `etc/init.d/vesper-packages` (+ `etc/runlevels/default/vesper-packages`): OpenRC oneshot that runs `apk add --quiet --no-progress --force-non-repository /var/lib/vesper/apks/*.apk` (the files are not in a repository, so apk needs the flag; they are verified against the Alpine keys on the boot media); on success creates `/run/vesper/packages-ready`; logs `vesper: …` lines to `/dev/console`; fails the service otherwise. Other Vesper services `need` it, which is how OpenRC orders them after the install.
- `etc/init.d/vesper-agent` (+ `etc/runlevels/default/vesper-agent`): `supervise-daemon`-supervised `socat -t 86400 VSOCK-LISTEN:<port>,reuseaddr,fork,max-children=64 EXEC:/usr/local/bin/vesper-agent` (port from `VESPER_AGENT_PORT`, default 1024; `-t` keeps relaying after a half-close, GH #167; at most 64 handlers at a time, since each `LAUNCHAPI` lease and `FCAPI` relay holds one, ADR 0007), `respawn_delay=1`, unlimited respawns; `need localmount vesper-packages`.
- `etc/init.d/vesper-vesperd-reaper` (+ `etc/runlevels/default/vesper-vesperd-reaper`): `supervise-daemon`-supervised `vesper-vesperd reap-loop 10` (interval from `VESPER_VESPERD_REAP_INTERVAL`); logs each reaped microVM to `/var/log/messages` as `vesperd-reaper: REAPED …`; its `start_pre` runs `vesper-vesperd setup-user`, which creates the `vesperd-jail` user and group (uid and gid 20000, shell `/sbin/nologin`, busybox `addgroup -S` and `adduser -S -D -H`; ADR 0007 slice 5); `need localmount vesper-packages`.
- `usr/local/bin/vesper-vesperd` (ADR 0007, slices 3 and 5): `vesperd`'s backend. `launch ID [CEILING] [stage=SRC:DEST]...` (the agent's `LAUNCHAPI`): checks the id (1 to 64 letters, digits, hyphens), the ceiling (bytes, 128 MiB to `MemTotal`, default 640 MiB) and at most 16 `stage=` tokens, refuses with `ERR data disk not in use` unless `/var/lib/vesper/state` is the data disk's ext4 bind mount and with `ERR no vesperd-jail user` without that user, takes the `flock` `/run/vesper/vesperd/lock`, runs a reaper pass, refuses an id with a record, jail or cgroup (`ERR busy ID`), runs `vesper-microvm prepare`, writes the record `/run/vesper/vesperd/leases/ID` (`holder=<pid>:<start> conn=<pid>:<start> fc=<pid>:<start>`, start = field 22 of `/proc/<pid>/stat`), copies `/Image` and `/initrd.gz` into `/var/lib/vesper/state/vesperd/jailer/firecracker/ID/root`, stages each token into that fresh jail outside the lock (`store:*.mem` and `store:*.vmstate` hard-linked, root-owned, mode 0444; everything else copied as below; `ERR stage SRC:DEST: <reason>`), starts the jailer as uid and gid 20000 with `--parent-cgroup vesperd`, `pids.max=256`, `memory.max=CEILING` and `-- --api-sock /run/firecracker.socket` (no config file), logs the serial console to `/var/log/vesperd/ID.log`, waits up to 10 s for the socket, reads and checks `firecracker.pid`, then prints `READY ID pid=N firecracker_version=V` (or `ERR <reason>` and exits). It then holds the lease: on end of file from the client, or when Firecracker exits, its `EXIT` trap stops Firecracker (SIGTERM, 3 s, SIGKILL) and removes the jail, the cgroup and the record, under the lock and only while the record is still its own. `connect ID` (the agent's `FCAPI`): `OK`, then `exec socat -t 86400 STDIO UNIX-CONNECT:/run/firecracker.socket,chroot-early=<jail root>`; `ERR bad id`, `ERR no vesperd microVM ID`, `ERR ID not ready`. `reap`: `REAPED ID reason=holder-gone|no-record … CLEAN ID` and `KEPT ID reason=holder-alive|grace` lines, then `REAP reaped=N kept=M`; a holder counts as alive only with its recorded start time; a jail without a record is spared for 60 s; a holder-gone reap also sends SIGTERM to the agent's socat for that connection, so the client sees the lease end. `reap-loop SECONDS`, `status ID` (`RUNNING ID pid=N holder=P`, `STARTING ID holder=P`, `ABSENT ID` or `DIRTY ID <record|jail|cgroup|process>`), `isolation ID` (JSON: `uid`, `jail`, `cgroup`, `memory_max`, `seccomp_mode`, `uid_ok`, `chroot_ok`, `cgroup_ok`, `seccomp_ok`), `list`, `log ID [N]`, `kill-holder ID`, `kill-fc ID`, and the test hooks `test-forge-start ID` (records a wrong holder start time, as if the pid were reused), `test-orphan ID` (a jail with no record), `test-age ID SECONDS` (backdates the jail directory) and `test-container-vsock` (a default and a `seccomp=unconfined` container from the trivial image, lent the System VM's socat, try `VSOCK-CONNECT` to CID 1 and 3; `VSOCK default=denied|allowed|connected|error cid=N detail=…` lines, exit 1 unless both default lines are `denied`). Slice 5 adds: `stage ID|- SRC DEST` (the agent's `VESPERD stage`; `SRC` `share:/PATH` under a virtio-fs mount, `store:NAME` or `jail:/PATH`; `DEST` a jail path or `store:NAME`; paths absolute, of letters, digits and `._+,@=-`, no `.` or `..` component, at most 1024 bytes; names at most 128 bytes, not starting with a dot; store to store and jail to jail refused; `ID` must hold a live lease when a jail side is named; refuses a symlink in any component below the share mount or jail root, a non-regular `SRC`, an existing `DEST`, and a copy that would leave less than the reserve (`MemTotal`, or `test-reserve`) free on the data disk; jail-side checks, reads and writes run as `vesperd-jail` through `su -s /bin/sh vesperd-jail -c` and the internal `jail-stat`, `jail-read`, `jail-write` and `jail-files` subcommands, which refuse any uid but 20000; new files are written with `set -C`; store copies go through `.partial.<pid>` and a rename; copies and store removals hold `/run/vesper/vesperd/store.lock`; `STAGED SRC DEST copy bytes=N` or `ERR <reason>`), `store-list` (`STORE NAME bytes=N links=L`, then `FREE avail=N reserve=N`), `store-rm NAME` (`REMOVED NAME`), `sweep` (every jail without a record and every `.partial.*` store file; `SWEPT jails=N partial=M`; run by `vesper-data mount`), `setup-user`, `files ID` (`FILE PATH uid= mode= links= bytes=` per regular file in the jail, listed as uid 20000), `memory ID` (`MEMORY ID current= peak= max= anon= file= shmem=` from the cgroup), and the test hooks `test-plant ID` (`/planted-link -> /etc/shadow`, `/planted-dir ->` the store, a root-owned mode 0600 `/planted-root`) and `test-reserve BYTES|clear` (`/run/vesper/vesperd/reserve`).
- `etc/init.d/vesper-docker-relay` (+ `etc/runlevels/default/vesper-docker-relay`): `supervise-daemon`-supervised `socat VSOCK-LISTEN:<port>,reuseaddr,fork UNIX-CONNECT:/var/run/docker.sock` (port from `VESPER_DOCKER_PORT`, default 2375); `need localmount vesper-packages vesper-services`. - `usr/local/bin/vesper-data` (GH #164): the persistent data disk, named on the kernel command line as `vesper_data=/dev/vdX`. `mount`: an empty disk (no filesystem found by `blkid`) is formatted ext4 with label `vesper-data` and lazy inode-table and journal init; an ext4 disk labelled `vesper-data` is mounted as it is; any other filesystem or label is refused and never formatted. One line per path, `TOUCHED <path>` (`TOUCHED <path> raced` when the third step ran), `SKIPPED <path> share-root|read-only-share`, `MISSING <path>`, `REJECTED <path> not-absolute|dotdot|outside-shares` or `ERR <path> touch-failed`; exit 1 when any path is rejected or fails), `notify` (the same for one absolute path per stdin line; greets `VESPER-SHARE-NOTIFY 1` and prints `NOTIFY touched= skipped= missing= rejected= errors=` on EOF). - `etc/init.d/vesper-binfmt`: mounts `binfmt_misc` and registers `/usr/bin/qemu-x86_64` for x86-64 ELF (magic and mask of the standard qemu entry) with flags `OCF`, skipping entries already present; prints `vesper: binfmt_misc registered N interpreter(s)` on the console; `stop` unregisters `qemu-*`.

## MicroVM execution (ADR 0006)

`vesper-microvm prepare` copies runc, socat, tini-static, `vesper-console` and their shared libraries
into the microVM initramfs. Package-lock and ISO verification cover their inputs.
`runtime.sha256` records copied bytes; the guest verifies it before execution.
A content stamp rebuilds an old initramfs when its scripts or runtime binaries change.
`vesper-microvm-init` holds the guest init separately from the manager script. Two command-line words serve the
ADR 0007 slice 5 suite: `vesper_fill_mib=N` writes N MiB of random bytes into a tmpfs of its own (`VESPER-FILL-OK
mib=N`), so the guest dirties that much memory, and `vesper_mark=1` keeps a random token in `/run/vesper-mark` and
prints `VESPER-MARK token=<hex> tick=<n>` every second, which a restored snapshot goes on printing.

`launch ID --rootfs PATH --runc-smoke` runs a fixed hello-world through runc and records kernel config
and available memory on the serial console. `--guest-exec` instead enables the private session service,
adds vsock and runs `tini-static` with socat on port 1025.
`vesper-guest-session` writes OCI configs verbatim, opens three socat stream relays and invokes runc.
It supports start, exec, signal, abort and terminal resize control requests.
`vesper-console` receives the terminal master through the existing containerd libraries.
It uses a guest-local Unix socket for resize; no descriptor crosses the VM boundary.
See [shim/README.md](../../shim/README.md) for the protocol and lifecycle contract.

`vesper-ctr run-stdio|run-tty|interactive|exec|exec-tty|exec-signal|signal-test|run-orphan|exit-with-exec`
provides the GH #23 hardware probes. `vesper-ptyrun` gives ctr a terminal, initially 24×80,
then resizes it to the supplied dimensions after three seconds.
The terminal proof binary comes from `shim/` and is installed by `build-overlay.sh`.

## Invariants

- Every file in this tree lands at the same path under `/` in the guest; the builder sets owner root, mode from the repository (executable bit preserved) and mtime 0, so the archive is deterministic.
- No secrets, no host paths, no package binaries live here: packages come from the cache that `scripts/systemvm/fetch-packages.sh` verifies against the packages lock.
- Scripts must be POSIX `sh` (busybox). A service that depends on an installed package must `need vesper-packages`.

## Side Effects

- At guest boot: `eth0` gets a DHCP lease; cgroup v2 is mounted; packages are installed into the tmpfs root on every boot (`/run/vesper/packages-ready`); `vesper-data mount` formats or mounts the data disk and prints `vesper: DATA …` on the console; `containerd` and `dockerd` start under `supervise-daemon` (`/run/vesper/services-ready`, logs under `/var/log/`); console lines prefixed `vesper:` are printed; `socat` listens on vsock port 1024 and spawns the agent per connection, and on vsock port 2375 relaying to the Docker socket.
- `vesper-data mount` formats an empty data disk once; afterwards writes by containerd, dockerd and the Vesper tools to the persistent directories change the disk image on macOS. `vesper-services stop` runs `vesper-data stop` after stopping the daemons.
- `KILL` sends SIGKILL to a daemon; supervise-daemon restarts it within about half a second.
- `MICROVM launch` starts a Firecracker process as uid 10000 in a jail with a cgroup; `cleanup` removes all of it.
- `LAUNCHAPI` starts a Firecracker process as uid 20000 in a jail under `/var/lib/vesper/state/vesperd/jailer` on the data disk with a cgroup under `/sys/fs/cgroup/vesperd`, writes a record under `/run/vesper/vesperd/leases` and a console log under `/var/log/vesperd`; the end of the lease, or the reaper, removes all of it except the console log. `VESPERD stage` writes files into a jail or the store `/var/lib/vesper/state/vesperd/store`, which outlives reboots; `store-rm` removes them; `vesper-data mount` removes every `vesperd` jail at boot. `setup-user` adds `vesperd-jail` to `/etc/passwd`, `/etc/group` and `/etc/shadow` in the tmpfs root. `vesper-vesperd-reaper` runs a pass every 10 s.

- `make systemvm-overlay` builds the archive; `make systemvm-boot-smoke` boots with it and the probe in the image lock requires `/run/vesper/packages-ready`, the installed binaries, the agent service and both runtime services; `make systemvm-up && make systemvm-services-suite` proves crash recovery.
