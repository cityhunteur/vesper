1. A request held unfinished across two saves (the judge's J-1 of D-056).
   `vesper-unfs probe --hold-remove hz/secret~ --until FILE --held-marker FILE2` mounts /s/0 as the guest, looks
   the name up, sends a REMOVE of it but for its last 4 bytes, makes FILE2, waits until FILE exists, and sends
   the rest. `--hold-create` does the same with an UNCHECKED CREATE. The server takes the call, looks at its list
   (the look at the start of every request), and then waits for the end of the arguments. After the held request
   the client makes and removes a file of its own in the export's root.
   unfs suite step held_request_judged_with_the_list_as_it_is_then: sources hold read-write and hold/hz/secret as
   a read-only file. The step waits for FILE2, then macOS saves hz/secret twice as an editor with a backup does,
   so hz/secret~ comes to be the file that was the read-only file between the saves; then FILE is made. First a
   held REMOVE (the name is absent when it is sent), then a held CREATE across two more saves.

   Control 1: a server built without the look at the list in either check of a request (`prot_refresh()` taken
   out of `exports_prot` and `exports_prot_follow`; the looks at the start of a request and on each loop turn
   kept). Run on the first form of the step, with the REMOVE only:
     attaches 0, 1 then 2; LIST unfs-h p=1 i=1 s=3; probe: HELD sent; HELD remove hz/secret~ status=OK;
     hz/secret~ was gone from macOS.
   So the request is held after the server's look at its start, and that look does not protect the file.

   Control 2: a server built without the look in `exports_prot_follow` only, which is the check that CREATE,
   SETATTR, WRITE, MKDIR, SYMLINK, MKNOD, LINK and COMMIT use; REMOVE, RMDIR and RENAME also use `exports_prot`:
     remove: HELD sent remove hz/secret~ (absent); HELD remove hz/secret~ status=ROFS; HELD control status=OK
     create: HELD sent create hz/secret~ (present); HELD create hz/secret~ status=OK; HELD control status=OK
   So the held REMOVE alone would not show the loss of that look, and the held CREATE does.
