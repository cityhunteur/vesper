   this step failed, as it should. Binds: a80:/d rw, a80/top:/t rw, a80/hy/secret:/b ro, a80/top/mid/conf:/c ro,
   a80/ed/leaf:/e ro, a80/rootconf:/rc ro, a80/own:/o ro. After macOS replaced top/mid (with conf in it) and

   /d/conf/keep. macOS replaces conf at the task's line 8; the server is killed at line 41 (in the second and
   third run).
     mv conf conf.old; mkdir conf (measure-aside-restart.txt): 2 lines wrote under both names (about half a
       second), then refused. /c/keep read "old" and /d/conf/keep "new". After the restart /c/keep gave "Stale
       file handle"; /d/conf/keep read "new"; writes refused.
     rm -r conf; mkdir conf (measure-remake.txt, measure-remake-restart.txt): 5 and 6 lines wrote under CONF
       (about a second and a half), none under conf; then refused. /c/keep and /d/conf/keep gave "No such file or
       directory" until the restart: the System VM kept the removed directory under the name's own spelling.
       After the restart /c/keep gave "Stale file handle" and /d/conf/keep read "new"; writes refused.
   So the task's own mount point of a directory bind does not follow a replaced directory (TD-083), and the
   window is about a second, up to about a second and a half when the directory is removed and made again.
